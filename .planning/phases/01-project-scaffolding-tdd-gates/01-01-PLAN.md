<objective>
Scaffold the repository as a TypeScript Homebridge dynamic-platform plugin: a correct package.json
(Homebridge engines, peerDependencies, the homebridge-plugin keyword), tsconfig.json compiling
src/ to dist/ via plain tsc, the stripped dynamic-platform skeleton (index.ts / platform.ts /
settings.ts), the config-UI schema, and the lint/format toolchain (ESLint 9 flat config + Prettier).
This is the foundation every later plan and phase builds on.

Purpose: Satisfy FND-01 — a buildable, conventionally-shaped Homebridge plugin skeleton with a
committed lockfile, so the TDD harness (Plan 02) and CI (Plan 03) have a project to gate.
Output: package.json + package-lock.json, tsconfig.json, eslint.config.mjs, .prettierrc.json,
.gitignore, config.schema.json, and src/{index,platform,settings}.ts compiling to dist/.

This phase BOOTSTRAPS the TDD harness, so per the ROADMAP note and FND-02 it is EXEMPT from the
test-first rule it establishes. Do NOT write a failing test before the scaffolding/config files.
The Homebridge-API glue (index.ts registration, platform.ts didFinishLaunching) carries a
`// tdd-audit: exempt` marker — these are thin adapters over the Homebridge API.
</objective>
